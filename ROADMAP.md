# FluentKit Roadmap

FluentKit aims to become a complete, modern declarative UI framework for native macOS desktop applications. Its public model should feel as coherent as SwiftUI while retaining direct AppKit interoperability and a Fluent-inspired visual language.

## Principles

- Native Swift API and native AppKit rendering.
- Declarative state, composition, navigation, commands, scenes, and presentation.
- Stable identity and localized reconciliation instead of rebuilding whole windows.
- macOS materials, typography, accessibility, responder routing, and platform conventions.
- No markup compatibility layer and no copied implementation code.
- MIT-licensed framework code with the reference-project notice kept separate.

## Completed Foundation

Milestones 1-13 provide the completed foundation: the declarative view protocol and builder, observable state and bindings, environment propagation, native layout and controls, stable-ID collections, materials, overlays, navigation, animation transactions, commands and menus, single- and multi-window scenes, frame restoration, focus routing, accessibility composition, a scrollable Gallery, Codable restored application state, native undo transactions, document sessions, sectioned diffable collections, native table and outline controls, adaptive grids, stable multi-selection, drag-reorder intents, large-data validation, and native input/form primitives. Milestone 14 now includes its foundational rich-text slice, Milestone 15 includes stable two-column navigation, destination registration, and typed navigation restoration, and Milestone 20 includes accessibility depth, localization, RTL propagation, and semantic audits.

## Planned Milestones

WindowShell state coverage now includes public Back and pane-header content, explicit native versus
extended title-bar behavior, optional search, title-bar or vertical-pane toggle placement, and
same-window switching between those states. Native configurations normalize unsupported Fluent
title-bar content instead of silently dropping a pane action; Top navigation suppresses both toggle
locations because it has no collapsible vertical pane. Window-owned presentation coordination now
serializes custom sheets, native confirmation alerts, and file panels with generation-safe binding
  writeback, focus restoration, and host-removal cancellation. Binding-driven Popover now owns
  automatic and directional placement, native behavior selection, Liquid Glass content, stable
  same-size updates, and geometry-safe presenter replacement. Multi-window restoration now persists
  scene-specific frames, the open window set, and the active stable ID while respecting disabled
  restoration policies and AppKit cascade behavior.

12. **Complete** Collection architecture: reusable diff snapshots, multi-selection, tables, outlines, grids, drag reordering, section headers, and large-data performance benchmarks. `FluentCollection` now also owns source-mapped ListViewItem and GridViewItem containers: 40pt list rows, 16/12 content padding, a 3 x 16 leading selection pill with 83ms/167ms state motion, GridView's 2pt accent plus 1pt inner selected edge, disabled opacity, keyboard focus, RTL, Reduce Motion, and stable chrome layering above arbitrary item content.
13. **Complete** Input and forms: secure fields, search fields, stable-value combo boxes, a dedicated NumberBox, range-clamped steppers, validation states, form sections, labels, semantic control sizing, and keyboard-default/cancel actions. NumberBox implements Hidden, Compact, and Inline spin-button placement; the Inline source geometry reserves a 72pt trailing column for adjacent RepeatButtons, while Compact owns a focus-scoped 48 x 88 popup with two 36 x 36 RepeatButtons. Empty input maps to `NaN`, and validation, wrapping, keyboard/page/wheel stepping, range boundaries, RTL, accessibility, and external bindings are verified. TextBox, PasswordBox, SearchBox, NumberBox, and editable ComboBox share one native field-editor bridge for source-derived selection and caret visuals while retaining AppKit IME, undo, accessibility, and responder behavior. Validation covers offscreen binding synchronization, native edit callbacks, invalid text recovery, selection cleanup, field-editor geometry, and accessibility state.
14. **In progress** Text system: the foundational slice is complete with attributed text and selection bindings, native undo, bold/italic/underline, font size, color, alignment, clear-format commands, formatting-state observation, find/replace, and stable-ID text attachment insertion/enumeration/removal. Rich-text selection keeps AppKit as the interaction owner, coalesces local drag-selection publication to the final range once per RunLoop turn, suppresses local binding echoes, and coalesces external ranges without replaying stale values. Stable observable binding identities now reuse RichTextEditor observers across declarative updates, while generation checks discard old asynchronous text/selection deliveries. Plain text controls replace AppKit's context menu with a source-structured TextCommandBarFlyout: mouse context commands use the secondary row presenter with available Cut/Copy/Paste/Select All commands, while touch-oriented primary commands retain the compact path. The command bar uses the source 83ms entrance opacity and immediate dismissal. Command execution remains delegated to the native field editor. Remaining work includes document-scale editor behavior, a complete attachment lifecycle, richer rich-text command routing, and integrated find UI.
15. **In progress** Navigation and presentation: stable-ID two-column navigation, a native resizable/collapsible sidebar, selection and visibility bindings, declarative detail/placeholder resolution, stale-selection cleanup, type-safe destination registration, homogeneous Codable path restoration, a native trailing inspector with width constraints and visibility binding, and in-place updates are complete. The public `FluentNavigationView` now supplies Left, Compact, Minimal overlay, automatic threshold, and Top modes; primary/footer destinations; separate pane/content headers; custom Top overflow; RTL; keyboard/accessibility behavior; bound pane state; and Gallery/validation coverage. It also owns the destination page presenter and exposes automatic, none, cross-fade, slide, drill-in, entrance, and suppress transition policies. Automatic mode maps ordered Top items to WinUI's recommended directional Slide path and other destinations to Entrance; outgoing/incoming retention, rapid replacement, Reduce Motion, and cleanup are framework behavior rather than Gallery wrappers. Public `FluentTitleBar` adds compact/expanded chrome, pane/back actions, icon/title/subtitle, three declarative slots, RTL/inactive states, native drag/double-click behavior, and reversible traffic-light-safe AppKit integration. Public `FluentWindowShell` composes independent native/extended title-bar, optional search, pane-toggle placement, vertical/horizontal navigation, backdrop, and content-corner axes into Standard, Compact, Minimal, Top, Settings, Document, Inspector, and Dialog presets. Its HeaderContent and page presenter share one clipped ContentSurface, and narrow title bars preserve interactive center content before truncating app identity. Custom Sheet, native ConfirmationDialog, FluentAlert, and file panels now share a window-owned FIFO presentation coordinator with generation-safe completion, focus restoration, host-removal cancellation, stable observer reuse, and in-place Sheet content/title/size/material updates. Binding-driven Popover now owns directional placement, native behavior, Liquid Glass content, focus restoration, and geometry-safe presenter replacement. Multi-window restoration now persists scene-specific frames, open set, and active stable ID. Navigation acceptance now covers source-asymmetric Entrance, Gallery-fixed BottomUp, Stack push/pop, duplicate route identities, and repeated cleanup. Restoration snapshots the launch active ID before opening windows, rejects non-finite frames, chooses the best visible screen, and contains partially off-screen frames. Remaining work is broader native window restoration and long-tail navigation acceptance.
16. **Complete** Motion system: public linear/ease timing curves, inherited Reduce Motion behavior, display-driven observable values, `@FluentAnimatedState`, physical springs with overshoot, normalized keyframes, scalar/geometry/inset/transform/color interpolation, visual transform modifiers, insertion/removal choreography, and matched geometry are complete. Transitions support move, scale, composition, asymmetric phases, deterministic cleanup, content-transform isolation, and namespace-scoped frame/size interpolation. `FluentAnimationCoordinator` and `FluentLayerAnimator` now provide the shared execution layer for presentation sampling, keyed interruption, model commits, Reduce Motion, and generation-safe completion without serializing unrelated controls through a global queue. Gallery and executable validation cover multi-property motion, exact final values, completion and timer release, duplicate keyframes, real underdamped overshoot, deterministic sampling, compatible update identity, composed branch replacement, reduced-motion replacement, matched-geometry entry lifecycle, and NavigationView-owned page replacement.
17. **In progress** Visual system and theming: the implementation scope is closed for semantic density, standard/high/system contrast, light/dark/system color schemes, observable application-level `FluentThemeStore`, semantic typography, reusable control styles, `FluentDesignTokens`, subtree variants for all three theme axes, and non-destructive accent/material derivation. The Gallery consumes public `FluentWindowShell`, `FluentNavigationView`, and `FluentTitleBar`, uses a shared behind-window Liquid Glass shell backdrop with an opaque fallback, keeps one shell-owned page heading, and separates category pages. Sixteen responsive Light/Dark/RTL baselines cover the current shell. The shared `FluentVisualStateCoordinator` provides state precedence, transition bookkeeping, unchanged-state suppression, and Reduce Motion policy; adoption currently covers ProgressBar, Button, RepeatButton, ToggleButton, DropDownButton, the closed ComboBox, CalendarDatePicker, and CollectionItem background/selection state. Button-like controls now share the source absolute 3pt elevation geometry, including the Light resource's bottom-edge `ScaleY=-1`; TextBox-family controls retain their distinct bottom 2pt TextControl elevation. Borderless/Subtle and Outline Button styles retain the source PointerOver fill and are covered through mounted pointer events plus declarative refresh. Inside fill-ring renderers keep all rounded edges within fixed AppKit hosts at 1x and 2x, so selected SegmentedControl surfaces and TextControl gradients cannot erase their leading/trailing boundaries. Their active selection uses `AccentFillColorSelectedTextBackgroundBrush`, selected text is white outside High Contrast, and the native caret resolves WinUI's white-plus-DestInvert result to opaque black in Light and white in Dark. The Dark semantic pass now maps the bundled Common resources exactly for text, control/card/layer fills, strokes, dividers, and on-accent foregrounds. `SystemAccentColor` is distinct from the theme-specific `AccentFillColor*` and `AccentTextFillColor*` palette; the default blue uses the source fallback variants exactly. NavigationView uses transparent expanded pane chrome and `LayerFillColorDefault` content surfaces instead of card fills. RepeatButton, ToggleButton, ToggleSwitch, Slider, CheckBox, RadioButton, SegmentedControl, SelectorBar, and ProgressBar have source-derived geometry and motion where a corresponding WinUI template exists, stable presentation layers, RTL, accessibility, Reduce Motion, validation, and Gallery coverage. RepeatButton maps press-mode invocation, 500ms delay, 33ms interval, cancellation, and the source 83ms background transition; ToggleButton maps every Checked and Indeterminate common-state combination through the shared coordinator. SelectorBar is a dedicated page/view selector with source-exact per-item pills; SegmentedControl remains a distinct FluentKit compact-selection control rather than being presented as WinUI SelectorBar. ProgressBar additionally supports determinate/indeterminate, paused, and error states with presentation-sampled value motion and a stable dual-layer indeterminate loop. ComboBox now has explicit selection and editable modes: selection centers the current item on the faceplate, while editable uses a native text editor and below/above popup layout; both share the source-derived host, focus states, item template, and separate popup motion. ComboBox rows and NavigationView items centralize PointerOver ownership in their host so scrolling, layout, focus loss, or dismissal cannot leave multiple hover fills. The native `NSComboBox` is a permanently transparent behavior/accessibility bridge, so AppKit dropdown chrome cannot appear. CalendarDatePicker has source-derived closed-state geometry and an explicit native `NSPopover` calendar boundary; exact WinUI calendar-grid rendering remains partial by design. Remaining work is coordinator adoption, long-tail component state acceptance, custom accent-palette refinement beyond the source default palette, and the remaining transient surfaces. A control is not visually complete merely because it has a declarative API or native AppKit backing.
18. **Complete** Motion fidelity foundation: public cubic-bezier curves and scene-specific `FluentMotionToken` values cover 83ms, 100ms, 150ms, 167ms, 250ms, 300ms, 333ms, 600ms, and 783ms motion. The shared list/NavigationView indicator reproduces vertical and horizontal two-indicator paths; NavigationView-owned Slide, Entrance, DrillIn, and Suppress page transitions use source-derived offsets, scale factors, phase boundaries, curves, completion cleanup, RTL direction, interruption, and Reduce Motion. Pane motion, matched geometry, gravity peak/shadow behavior, and MenuFlyout's dedicated 250ms entrance retain executable coverage. Component-specific state machines remain Milestone 17 visual-acceptance work.
19. **In progress** Application flyouts and menus: the macOS main menu remains on `NSMenu`; in-app `Button.Flyout`, `DropDownButton`, context menus, nested submenus, and TextControl command surfaces use application-owned Fluent presenters, while ComboBox owns a separate popup and item template. Functional behavior includes custom rows, checks, separators, accelerators, keyboard/type-ahead navigation, Escape/outside-click dismissal, accessibility, RTL, delayed pointer submenu expansion, and left-click Gallery entry points. Text commands derive their contents from the active AppKit editor and never replace its clipboard or undo implementation. Mouse invocation follows WinUI's secondary-only TextCommandBarFlyout path; input-device-preferred primary composition uses 40pt icon commands plus More, whose secondary expansion commits final geometry before a source 250ms clip transition. Public `FluentCommandBarFlyout` now exposes PrimaryCommands, SecondaryCommands, `AlwaysExpanded`, action/toggle/separator items, direct presentation, and a regular Button attachment while reusing that verified geometry and clip lifecycle. DropDownButton opens only after pointer-up inside; release outside cancels, and clicking an open DropDownButton or ordinary `Button.Flyout` closes the existing presenter without allocating a replacement. MenuFlyout uses presenter-wide 28pt check/system-icon placeholders, 16pt icons, source narrow padding, accelerator and submenu trailing columns, and RTL slot mirroring. It uses the source-derived 250ms whole-presenter translation, inverse clip translation, and border expansion: root presenters move by 50% and submenus by 67%. Its High Contrast rows resolve the system Highlight/HighlightText/GrayText resources and the presenter keeps the source 2pt system border. Selection ComboBox instead runs a 250ms SplitOpen clip centered on the current item, growing the initial clip near an edge without shifting that center; editable ComboBox uses the one-sided below/above path. MenuFlyout and both ComboBox modes dismiss immediately with no exit animation. Transient and navigation surfaces now resolve to native Liquid Glass through the theme's global `materialEffectsEnabled` switch, with an opaque Fluent fallback when disabled; menus, ComboBox popups, NavigationView panes, popovers, teaching tips, inspectors, and text command surfaces share that switch without changing ownership or layout. Visual acceptance remains open for arbitrary custom menu content and normalized increased-contrast comparisons across the remaining flyout family.
20. **Complete** Accessibility and localization: semantic child behaviors, custom actions, focus announcements, rotor support, dynamic labels, RTL layout, localization helpers, and automated tree audits. Gallery coverage includes an Accessibility page and Light/Dark/RTL snapshots; the shared list selection rail follows the leading edge in RTL.
21. **Complete** Application services: native `FluentSettingsScene`, semantic window roles, automatic/preferred/disallowed native tabbing, Command-comma settings routing, open-file and open-URL callbacks, reopen fallback, declarative Dock menus, binding-driven native import/export panels, document import/export semantics, atomic versioned state migration, declarative native Services providers, print and share presenter boundaries, and multi-document coordination are complete with Gallery and executable coverage. Services provider discovery still follows the app bundle's standard `NSServices` metadata.
22. **In progress** Production hardening: the `0.1.0` release baseline, compatibility policy, changelog, API examples, and native Gallery snapshot inventory are documented. Executable validation now checks every documented baseline for existence, dimensions, and rendered pixel variation; layout/motion coverage includes divider orientation, list-rail alignment, same-level two-indicator navigation choreography, rapid page-transition coalescing, deterministic transition cleanup, reusable NavigationView adaptive/Top paths, cross-level primary/footer motion, overflow actions, RTL, and Reduce Motion. Responsive Minimal Light/Dark and Top Light/Dark/RTL captures complement the desktop Gallery set. Remaining work includes broader performance/leak coverage and full-Xcode XCTest integration when a toolchain providing `XCTest` is available.

Each milestone must include public API documentation, executable validation, a Gallery example where visual behavior is involved, strict warning-free builds, and native bitmap regression checks for user-facing changes.
