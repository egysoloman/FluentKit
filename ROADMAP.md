# FluentKit Roadmap

FluentKit aims to become a complete, modern declarative UI framework for native macOS desktop applications. Its public model should feel as coherent as SwiftUI while retaining direct AppKit interoperability and a Fluent-inspired visual language.

## Principles

- Native Swift API and native AppKit rendering.
- Declarative state, composition, navigation, commands, scenes, and presentation.
- Stable identity and localized reconciliation instead of rebuilding whole windows.
- macOS materials, typography, accessibility, responder routing, and platform conventions.
- No markup compatibility layer and no copied implementation code.
- MIT-licensed framework code with the reference-project notice kept separate.

## Completed Foundation

Milestones 1-13 provide the completed foundation: the declarative view protocol and builder, observable state and bindings, environment propagation, native layout and controls, stable-ID collections, materials, overlays, navigation, animation transactions, commands and menus, single- and multi-window scenes, frame restoration, focus routing, accessibility composition, a scrollable Gallery, Codable restored application state, native undo transactions, document sessions, sectioned diffable collections, native table and outline controls, adaptive grids, stable multi-selection, drag-reorder intents, large-data validation, and native input/form primitives. Milestone 14 now includes its foundational rich-text slice, Milestone 15 includes stable two-column navigation, destination registration, and typed navigation restoration, and Milestone 20 includes accessibility depth, localization, RTL propagation, and semantic audits.

## Planned Milestones

12. **Complete** Collection architecture: reusable diff snapshots, multi-selection, tables, outlines, grids, drag reordering, section headers, and large-data performance benchmarks.
13. **Complete** Input and forms: secure fields, search fields, stable-value combo boxes, range-clamped steppers, validation states, form sections, labels, semantic control sizing, and keyboard-default/cancel actions. Validation covers offscreen binding synchronization, native edit callbacks, invalid text recovery, selection cleanup, and accessibility state.
14. **In progress** Text system: the foundational slice is complete with attributed text and selection bindings, native undo, bold/italic/underline, font size, color, alignment, clear-format commands, formatting-state observation, find/replace, and stable-ID text attachment insertion/enumeration/removal. Remaining work includes document-scale editor behavior, a complete attachment lifecycle, richer command routing, and integrated find UI.
15. **In progress** Navigation and presentation: stable-ID two-column navigation, a native resizable/collapsible sidebar, selection and visibility bindings, declarative detail/placeholder resolution, stale-selection cleanup, type-safe destination registration, homogeneous Codable path restoration, a native trailing inspector with width constraints and visibility binding, in-place updates, and Gallery/validation coverage are complete. Remaining work includes richer sheets and presentation coordination.
16. **Complete** Motion system: public linear/ease timing curves, inherited Reduce Motion behavior, display-driven observable values, `@FluentAnimatedState`, physical springs with overshoot, normalized keyframes, scalar/geometry/inset/transform/color interpolation, visual transform modifiers, insertion/removal choreography, and matched geometry are complete. Transitions support move, scale, composition, asymmetric phases, deterministic cleanup, content-transform isolation, and namespace-scoped frame/size interpolation. Gallery and executable validation cover multi-property motion, exact final values, completion and timer release, duplicate keyframes, real underdamped overshoot, deterministic sampling, compatible update identity, composed branch replacement, reduced-motion replacement, and matched-geometry entry lifecycle.
17. **In progress** Visual system and theming: the implementation scope is closed for semantic density, standard/high/system contrast, light/dark/system color schemes, observable application-level `FluentThemeStore`, semantic typography, reusable control styles, `FluentDesignTokens`, subtree variants for all three theme axes, and non-destructive accent/material derivation. Default Button, Toggle, Slider, TextField, Progress, CheckBox, Radio, Segmented, and Card styles now share high-contrast emphasis rules with executable coverage. The Gallery uses a fixed Mica surface, a left NavigationView-style shell, one content header instead of a second native toolbar, and separate Overview, Controls, Inputs, Collections, Navigation, and Motion pages. Remaining acceptance work is the deferred Light/Dark bitmap pass for icon geometry, field chrome, state layers, and surface matching. A control is not considered visually complete merely because it has a declarative API or native AppKit backing.
18. **Complete** Motion fidelity: public cubic-bezier curves and scene-specific `FluentMotionToken` values cover 83ms, 167ms, 250ms, 300ms, and 600ms motion. Button brush transitions, ToggleSwitch hover/pressed thumb geometry, a shared cross-row list/navigation indicator, and symmetric flyout open/close geometry consume these tokens. Matched geometry offers automatic 300ms, direct 200ms, and gravity 300ms configurations; gravity includes a 66% peak with 80pt lift, 1.1 scale, and temporary shadow, and transition cleanup respects the longest participating motion. Gallery navigation now uses the shared list indicator, segmented controls animate a single custom selection surface through position, scale, and opacity, and `FluentTeachingTip` provides an application-owned Acrylic child panel with directional open/close choreography, tail placement, focus, Escape/outside-click dismissal, binding synchronization, and Reduce Motion behavior. Gallery examples, native Light/Dark bitmap checks, and executable validation cover the completed slice. The Milestone 16 animation engine remains the execution foundation; this milestone supplies the Fluent timing and choreography fidelity layer.
19. **Complete** Application flyouts and menus: the macOS main menu remains on `NSMenu`, while in-app menu buttons and context menus use an application-owned Acrylic `FluentMenuFlyout` panel with 8pt radius, 1pt border, tokenized presenter/item padding, 32pt rows, hover/pressed/disabled states, checkmarks, separators, accelerators, keyboard navigation, Escape/outside-click dismissal, accessibility roles, and open/close motion. `FluentMenuItem` now supports nested submenu data and Fluent chevrons; submenu panels open immediately from keyboard/accessibility input or after a 180ms pointer hover delay, preserve focus-level Escape/Left/Right navigation, perform type-ahead matching, and mirror anchor placement and glyph columns for RTL layouts. ComboBox fields retain native `NSComboBox` identity while routing option presentation through the same application-owned flyout instead of the AppKit popup. Gallery includes nested account actions, and executable validation covers menu trees, delayed expansion, type-ahead, RTL alignment, accessibility states, submenu actions, and custom ComboBox presentation.
20. **Complete** Accessibility and localization: semantic child behaviors, custom actions, focus announcements, rotor support, dynamic labels, RTL layout, localization helpers, and automated tree audits. Gallery coverage includes an Accessibility page and Light/Dark/RTL snapshots; the shared list selection rail follows the leading edge in RTL.
21. **Complete** Application services: native `FluentSettingsScene`, semantic window roles, automatic/preferred/disallowed native tabbing, Command-comma settings routing, open-file and open-URL callbacks, reopen fallback, declarative Dock menus, binding-driven native import/export panels, document import/export semantics, atomic versioned state migration, declarative native Services providers, print and share presenter boundaries, and multi-document coordination are complete with Gallery and executable coverage. Services provider discovery still follows the app bundle's standard `NSServices` metadata.
22. **In progress** Production hardening: the `0.1.0` release baseline, compatibility policy, changelog, API examples, and native Gallery snapshot inventory are documented. Executable validation now checks every documented baseline for existence, dimensions, and rendered pixel variation; layout/motion coverage includes divider orientation, list-rail alignment, rapid page-transition coalescing, and deterministic transition cleanup. Controls/Inputs Light and Dark captures have been regenerated after the layout pass. Remaining work includes broader performance/leak coverage and full-Xcode XCTest integration when a toolchain providing `XCTest` is available. The WinUI two-indicator NavigationView choreography remains a separate visual-fidelity acceptance item and is not considered complete.

Each milestone must include public API documentation, executable validation, a Gallery example where visual behavior is involved, strict warning-free builds, and native bitmap regression checks for user-facing changes.
