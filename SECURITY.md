# Security Policy

## Supported versions

Security fixes are applied to the latest release line and the `main` branch.

| Version | Supported |
| --- | --- |
| `main` | Yes |
| 0.1.x | Yes |
| Earlier versions | No |

## Reporting a vulnerability

Do not disclose potential vulnerabilities in a public issue, discussion, or pull request.

Use GitHub's private vulnerability reporting option from the repository's **Security** tab when it
is available. Include the affected version or commit, impact, reproduction conditions, and any
suggested mitigation. If private reporting is unavailable, open a minimal public issue asking the
maintainers to establish a private contact channel, without including vulnerability details.

Maintainers will acknowledge a complete report, evaluate its scope, and coordinate disclosure and a
fix when the report is valid. Please allow time for a patch to be prepared before public disclosure.

Only test repositories, applications, and systems that you own or are explicitly authorized to
assess.
